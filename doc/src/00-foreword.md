# 前言：这本手册怎么用

这本手册是 KataHana 项目的开发文档，面向后续在这个仓库上继续开发的工程师。
它不重复 README 里的“如何安装、如何开局”，而是回答两类问题：

1. **这个项目长什么样**——代码放在哪里、每个模块干什么、依赖怎么走、状态怎么流转、
   协议怎么工作；
2. **改起来要注意什么**——哪些是不可破坏的约定、关键机制的清除条件是什么、测什么、
   怎么验证。

## 开发前置条件：先懂围棋

KataHana 的核心代码就是在执行、展示和询问围棋。在对围棋规则本身没有基本了解的
情况下开发核心功能（棋规、棋树、会话、棋盘渲染、引擎协议），几乎必然写出错误的
合法着判定或错误的分析展示。

不要求你会下棋，但必须能独立说清：气、提子、自杀、打劫 / superko、真眼与假眼、
虚着终局，立 / 尖 / 飞 / 跳 / 虎以及拆、双关这些形，布局 / 中盘 / 官子在争什么，
以及「金角银边草肚皮」和高低搭配。这些内容集中在下一章
《围棋入门：规则与基本手法》。**请先读完那一章，再开始改 `domain/`、`engine/`、
`ui/board/`、`ui/session/`。**

## 阅读建议

- 第一次接触项目：先读《围棋入门》，再读第 1 章建立整体图景，然后读第 4 章
  （会话状态与数据流）和第 6 章（引擎协议）。后两章是本项目最核心、也最容易改坏
  的部分。
- 只改某一处功能：先查第 8.8 节“速查表”，找到对应源码位置，再读对应章节的细节。
- 任何一次修改：请遵守第 8.7 节“文档同步义务”——本手册是活文档，改了模块的行为、
  API、协议或 UI 结构，就要在同一提交里更新对应章节。

## 写作原则

手册对**关键/核心功能**不只写“有什么、在哪、怎么调”，而是写明**实现原理**：
某个机制由哪些状态与调用构成、数据从哪来、状态如何流转、边界与清除条件是什么、
以及为什么这样设计。阅读时如果发现某一节只停留在“罗列”，那多半是文档还没写完，
欢迎补上“为什么”。

## 术语约定

代码里的标识符、文件名、协议字段一律保留英文原文；叙述用中文。少量需要区分的概念：

| 术语 | 含义 |
| --- | --- |
| 复盘（review） | `GameTree.current` 不在叶子上、存在可继续走的后续（`reviewing == canRedo`）的状态 |
| 变着 / 分支 | 同一手棋下的多个可选后续，在树上是同一父节点的多个 `children` |
| 主变（preferred line） | 从根节点沿 `preferredChild` 一路走到叶子的那条线 |
| 虚子（virtual stone） | 局势预测渲染出来的、未真正落子的半透明棋子，只存在于 `Forecast` |
| 引擎 / 网关 | “引擎”指 KataGo；“网关”指 `engine/server.py` 这个中转进程 |
| 胜负条、势力图、候选点 | UI 术语，见第 5 章 |
| 立 / 尖 / 飞 / 跳 / 虎 | 基本行棋手法，见《围棋入门》；代码里对应 `LinkKind.Nobi/Kosumi/Keima/Tobi`（虎无对应枚举） |
| 真眼 / 假眼 | 围眼的棋是否已连成整体；角、边、腹的眼角数量不同，见《围棋入门》 |
| 拆二 / 双关 / 空三角 | 边上生根、厚实出头、典型愚形；见《围棋入门》棋形一节 |
